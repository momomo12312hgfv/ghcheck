# Rule catalog

Every rule ghcheck can report. Generated by `bun run docs`; do not edit by hand.

## Token capability analyzer (`token`)

Works out what the GITHUB_TOKEN of each job can do, and reports every write permission it is granted.

### critical

#### `token.write-all-permissions`

**GITHUB_TOKEN is granted every permission**

`permissions: write-all` gives the job a token that can change anything the repository can change.

**Fix**: List the permissions the job actually needs instead of `write-all`.

### high

#### `token.write-permission`

**GITHUB_TOKEN has a write permission**

A write permission on GITHUB_TOKEN turns a compromised step into repository access.

**Fix**: Drop the permission, or split the job so that the write step runs separately.

### medium

#### `token.permissions-not-declared`

**GITHUB_TOKEN permissions are not declared**

The job does not declare `permissions:`, so the token gets whatever the repository default is. On older repositories that default still includes write access.

**Fix**: Declare `permissions:` explicitly on the workflow or on every job.

## Workflow auditor (`workflow`)

Audits GitHub Actions workflows for script injection, privileged triggers, unpinned and retired actions, and secret inheritance.

### critical

#### `workflow.script-injection`

**Untrusted input is interpolated into a shell command**

A `run:` step interpolates attacker-controlled text through `${{ }}`. Anyone who can open a pull request or an issue can run code in this job.

**Fix**: Pass the value through an environment variable and quote it: set `env: TITLE: ${{ github.event.pull_request.title }}` and use `"$TITLE"` in the script.

#### `workflow.privileged-checkout`

**Privileged trigger checks out attacker-controlled code**

This workflow runs on a privileged trigger and then checks out code the attacker controls, so that code executes with the job's secrets and token.

**Fix**: Do not check out the pull request head in a privileged workflow, or drop the job's privileges before checking out.

### high

#### `workflow.dangerous-trigger`

**Workflow uses a privileged trigger**

This trigger runs the workflow with repository secrets and a writable GITHUB_TOKEN.

**Fix**: Use `pull_request` for untrusted code, and keep `pull_request_target` for workflows that never check out the pull request head.

#### `workflow.secrets-inherit`

**Reusable workflow inherits every secret**

`secrets: inherit` hands the called workflow every secret of the caller, including the ones it does not need.

**Fix**: Pass only the secrets the called workflow needs.

### medium

#### `workflow.invalid-yaml`

**Workflow file is not valid YAML**

The workflow could not be parsed, so none of the workflow checks could run against it.

**Fix**: Fix the YAML syntax. `actionlint` reports the exact line.

#### `workflow.unpinned-action`

**Action is not pinned to a commit SHA**

The action is referenced by tag or branch, so the code that runs can change without any commit to this repository.

**Fix**: Pin the action to a full commit SHA and keep the version in a trailing comment.

#### `workflow.deprecated-action`

**Action version is retired**

This action version no longer runs on current GitHub infrastructure.

**Fix**: Upgrade the action to its current major version.

#### `workflow.self-hosted-runner`

**Job runs on a self-hosted runner**

Self-hosted runners are not ephemeral, so code from a pull request can leave files and processes behind.

**Fix**: Use GitHub-hosted runners for untrusted workflows, or isolate the runner between jobs.

### low

#### `workflow.docker-unpinned`

**Container image is not pinned**

The container image can change between runs, so the same workflow can behave differently tomorrow.

**Fix**: Pin the image to a digest.

## Secret scanner (`secret`)

Finds committed credentials: GitHub, AWS, private keys, Slack, Stripe, LLM API keys, database URLs and high-entropy values.

### critical

#### `secret.github-fine-grained-token`

**Hardcoded fine-grained GitHub token**

A fine-grained personal access token is committed in this file. Anyone who can read the repository can act as its owner until it is revoked.

**Fix**: Revoke the token in GitHub Settings > Developer settings, then read it from the environment or a secret store instead.

#### `secret.github-token`

**Hardcoded GitHub token**

A classic PAT, OAuth or GitHub App token is committed in this file. Its blast radius depends on the scopes it carries.

**Fix**: Revoke the token, then read it from the environment or a secret store instead.

#### `secret.aws-access-key-id`

**Hardcoded AWS access key id**

An AWS access key id is committed in this file. Paired with a secret key it grants full access to the account.

**Fix**: Deactivate the key in the AWS console, then read it from the environment or a secret store instead.

#### `secret.aws-secret-access-key`

**Hardcoded AWS secret access key**

An AWS secret access key is committed in this file. It is enough to sign requests as the owning IAM user.

**Fix**: Rotate the key in the AWS console, then read it from the environment or a secret store instead.

#### `secret.private-key`

**Private key committed**

A private key block is committed in this file. It may grant access to a server, a code-signing identity or a certificate.

**Fix**: Remove the key from the repository, rotate it, and use a secret store or an encrypted vault instead.

### high

#### `secret.slack-token`

**Hardcoded Slack token**

A Slack API token is committed in this file.

**Fix**: Revoke the token in the Slack app admin page, then load it from the environment.

#### `secret.slack-webhook`

**Hardcoded Slack webhook URL**

A Slack incoming webhook URL is committed in this file. Anyone holding it can post into the channel.

**Fix**: Recreate the webhook in the Slack app admin page, then load it from the environment.

#### `secret.stripe-key`

**Hardcoded Stripe secret key**

A Stripe live or test secret key is committed in this file. Live keys can move money and read customer data.

**Fix**: Roll the key in the Stripe dashboard, then load it from the environment.

#### `secret.anthropic-key`

**Hardcoded Anthropic API key**

An Anthropic API key is committed in this file.

**Fix**: Revoke the key in the Anthropic console, then load it from the environment.

#### `secret.openai-key`

**Hardcoded OpenAI API key**

An OpenAI API key is committed in this file.

**Fix**: Revoke the key in the OpenAI dashboard, then load it from the environment.

#### `secret.google-api-key`

**Hardcoded Google API key**

A Google API key is committed in this file.

**Fix**: Delete the key in the Google Cloud console, then load it from the environment.

#### `secret.npm-token`

**Hardcoded npm access token**

An npm access token is committed in this file. It can publish packages under your account.

**Fix**: Revoke the token in npm settings, then load it from the environment.

#### `secret.pypi-token`

**Hardcoded PyPI upload token**

A PyPI API token is committed in this file. It can publish packages to your account.

**Fix**: Revoke the token in PyPI settings, then load it from the environment.

#### `secret.database-url`

**Hardcoded database connection string**

A database URL with an inline password is committed in this file. It usually points straight at production.

**Fix**: Rotate the database password, then read the URL from the environment.

### medium

#### `secret.basic-auth-url`

**Credentials embedded in a URL**

A URL carries an inline user:password pair. It leaks through logs, referrers and shell history.

**Fix**: Move the credentials into a secret store and reference them from the environment.

#### `secret.generic-credential`

**Hardcoded credential assignment**

A value assigned to a password, secret or token-looking name is committed in this file.

**Fix**: Move the value into a secret store and read it from the environment.

### low

#### `secret.high-entropy-value`

**High-entropy value assigned in source**

A long, high-entropy string is assigned to a variable. It is not proof of a secret, but it is the shape of one.

**Fix**: Confirm the value is not a credential; if it is, move it into a secret store.

## Suppression

One syntax works for every rule, in every analyzer:

```yaml
# ghcheck: ignore workflow.script-injection   # suppress that rule on this line
# ghcheck: ignore rule-a, rule-b              # several rules on this line
# ghcheck: ignore-all                          # every rule on this line
# ghcheck: ignore-file                         # every rule in this file
```
